## Project Overview

**dev-cli** is a Windows-first CLI tool for managing Git repositories and launching them in IDEs. The project demonstrates best practices for building production-quality Rust CLI applications.

- **Language:** Rust 2024 edition
- **MSRV:** 1.88+
- **Version:** 0.1.0
- **Status:** Beta (documentation pass in progress)

## Architecture

The codebase follows strict **four-layer architecture** with NO upward dependencies:

```
Layer 1: CLI          (cli.rs, main.rs) — Parse arguments
   ↓
Layer 2: Commands     (commands/*.rs) — Dispatch handlers
   ↓
Layer 3: Services     (config.rs, ide/*.rs, installer.rs) — Business logic
   ↓
Layer 4: Models       (models/*.rs) — Data structures
```

**Critical Rule:** No layer depends on any layer above it. Verify this in every change.

## Code Quality Standards

### Formatting & Linting

All code must pass:

```bash
cargo fmt                      # Code formatting (Rust standard)
cargo clippy -- -D warnings    # No clippy warnings allowed
cargo test                     # All tests pass
cargo doc --no-deps            # No missing documentation
```

Run before every commit:

```bash
cargo fmt && cargo clippy && cargo test && cargo doc --no-deps
```

### Documentation

**Every public item MUST have rustdoc:**

```rust
/// Brief one-line description.
///
/// More detailed explanation if behavior is non-obvious.
///
/// # Errors
/// When and why this can fail.
///
/// # Examples
/// ```no_run
/// let result = function()?;
/// ```
pub fn function() -> Result<String> { }
```

**Module-level documentation** required in all files:

```rust
//! What this module does.
//! 
//! # Responsibilities
//! - Item 1
//! - Item 2
```

### Error Handling

**Always use `Result<T>` for fallible operations:**

```rust
// ✅ Good
pub fn load() -> Result<Config> { }

// ❌ Never
pub fn load() -> Option<Config> { }
pub fn load() -> Config { }  // Can panic!
```

**Always add context:**

```rust
// ✅ Good
Config::load()
    .context("Failed to load user configuration")?

// ❌ Never
Config::load().unwrap()
```

### Module Size

| Module Type | Target | Maximum |
|------------|--------|---------|
| Single-function | < 50 lines | 100 lines |
| Utility | 100-200 lines | 300 lines |
| Feature | 200-300 lines | 500 lines |

If > 500 lines, split into submodules.

## Adding Features

### Checklist

Before adding any feature, verify:

**Code Quality:**
- [ ] New code doesn't violate 4-layer architecture
- [ ] Public APIs have comprehensive rustdoc with # Examples
- [ ] Error handling uses Result + context
- [ ] Tests exist (unit + integration)
- [ ] All tests pass
- [ ] Code passes clippy and rustfmt

**Documentation (REQUIRED - Not Optional):**
- [ ] Rustdoc added/updated for all public APIs
- [ ] Module-level documentation updated
- [ ] CHANGELOG.md updated (Unreleased section)
- [ ] Relevant docs/ guide updated if user-facing
- [ ] ARCHITECTURE.md updated if structure changes
- [ ] README.md updated if feature is major
- [ ] Examples are accurate and functional
- [ ] No warnings from `cargo doc --no-deps`

**Final Verification:**
- [ ] Run: `cargo fmt && cargo clippy && cargo test && cargo doc --no-deps`
- [ ] All checks pass
- [ ] Code and docs committed together

### Process (Documentation-Driven)

1. **Design & Document** — Plan structure AND write architecture docs
2. **Implement** — Write rustdoc BEFORE implementing
3. **Test** — Write tests while developing
4. **Update Guides** — Update user guides, CHANGELOG.md, README
5. **Verify** — All quality checks pass (including `cargo doc`)
6. **Commit** — Code + docs together (never separate)

## Testing

### Unit Tests

In same file, `#[cfg(test)]` module:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_name_condition() {
        // Test here
    }
}
```

### Integration Tests

In `tests/` directory, one file per command:

- `tests/cli_config.rs`
- `tests/cli_ide.rs`
- `tests/cli_project.rs`

Use `assert_cmd` and `predicates` crates.

### Running Tests

```bash
cargo test              # Run all
cargo test -- --nocapture  # Show output
cargo test --test cli_config  # Specific file
```

## File Organization

### Adding a New Command

**Complete checklist (CODE + DOCUMENTATION):**

1. Create `src/commands/new_command.rs` with module-level `//!` docs
2. Add variant to `Commands` enum in `cli.rs` (with rustdoc)
3. Add match arm to `main.rs`
4. Implement `pub fn execute()` with comprehensive rustdoc
5. Add tests to `tests/cli_new_command.rs`
6. **Update README.md** command reference section
7. **Create/update docs/ guide** explaining the command
8. **Update CHANGELOG.md** with new feature
9. **Update ARCHITECTURE.md** if significant
10. Verify: `cargo fmt && cargo clippy && cargo test && cargo doc --no-deps`

Example structure (with docs):

```rust
// src/commands/new_command.rs
//! Implementation of 'dev new-command' for [explaining purpose].

/// Execute new command.
///
/// [Detailed explanation of what it does]
///
/// # Errors
/// Returns error if [conditions]
pub fn execute(args: NewCommandArgs) -> Result<()> {
    match args.subcommand {
        SubcommandType::Option1 => option1(),
        SubcommandType::Option2 => option2(),
    }
}

fn option1() -> Result<()> { }
fn option2() -> Result<()> { }
```

### Adding a New Service

1. Create `src/service_name.rs` with module-level `//!` docs
2. Implement public functions with comprehensive rustdoc
3. Add # Errors and # Examples sections
4. Add to module hierarchy
5. Write unit tests in same file
6. **Update docs/project-structure.md**
7. **Update CHANGELOG.md**
8. Never call upward layers (enforce architecture)
9. Verify: `cargo doc --no-deps` passes

### Adding a New Model

1. Create `src/models/new_type.rs`
2. Define struct/enum with derives
3. Add rustdoc
4. Add constructors if needed
5. Add to `src/models/mod.rs`

## Common Patterns

### Early Return

```rust
pub fn find_project(name: &str) -> Result<PathBuf> {
    if name.is_empty() {
        bail!("Name cannot be empty");
    }
    
    let config = Config::load()?;
    
    for root in config.projects_root {
        let path = root.join(name);
        if path.exists() {
            return Ok(path);
        }
    }
    
    bail!("Project not found")
}
```

### Option Handling

```rust
// ✅ Simple cases
let ide = args.ide.unwrap_or(config.default_ide);

// ✅ Complex cases
match maybe_value {
    Some(v) => process(v)?,
    None => default_action(),
}
```

### Error Context

```rust
fs::read_to_string(&path)
    .context(format!("Failed to read {}", path.display()))?

fn operation() -> Result<()> {
    helper()
        .context("Operation failed")?;
    Ok(())
}
```
